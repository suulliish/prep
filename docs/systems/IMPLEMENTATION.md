Третий консилиум, 02.10.2026. Шесть инженерных спецификаций по решениям Султана (`docs/DECISIONS.md`) и реальному коду лежат в `docs/systems/specs/`:

| Префикс PR | Часть | Спецификация |
|---|---|---|
| **S** | данные, синхронизация, безопасность выпусков | `specs/data.md` |
| **L** | правила знания: уровни тем, проверки, трещины, очередь, пробник | `specs/learning.md` |
| **D** | день ребёнка: два рейса, минуты, свернул, караоке, корабль | `specs/day.md` |
| **P** | прогрессия: деңгей, 49 вех, миры, боссы, монеты, мастерская, питомец, коллекция | `specs/progression.md` |
| **C** | контент: очередь 151 темы, генераторы, виджеты, пробники, проверка казахского | `specs/content.md` |
| **K** | командир: PIN, без подарков, серия, исключения, неделя, тревоги, прогноз | `specs/commander.md` |

Что строим — `MASTERPLAN.md` (словарь §1) и `DESIGN.md`. Здесь — **как и в каком порядке**, и как сведены расхождения между спецификациями.

## 1. Сведённые расхождения (обязательны для всех PR)

1. **Уровни тем — свёртка из ответов.** `foldTopics(topicsBase, attempts ≥ base.at, exceptions)` (L) — единственный источник; `save.topics` — кэш, после слияния устройств пересчитывается, полевого слияния тем нет. Уровень = max(кэш, свёртка). Снимок `topicsBase` — по понедельникам (правила с понедельника).
2. **Прогрессия — в одном месте `save.prog`** (P): `skins` (= «открытое», только растёт), `ms` (вехи), `earned` (журнал монет по ключам `L:тема:ур`, `M:…`, `F:…`, `B:мир`, `m:день`, `A:день`, `past`), `bought`, `rooms`, `cards`, питомец. Поля `unlocked/milestones/ledger/pets/collection` из `specs/data.md` не заводим — их правила слияния (объединение, максимум) применяются к `prog`.
3. **Ремонт минут — `save.debts`** (D). `RepairTask` из `specs/data.md` не заводим. Обычный `repairShop` остаётся только для переполнения переноса (> 8 близнецов).
4. **Монеты — только за события освоения** (таблица P). За ремонт долгов минут **0 монет всегда** (в т.ч. перенесённых; в `specs/day.md` было 1 — отменено). Починка трещины — 3, не чаще раза в 30 дней на тему.
5. **PIN** — по K: PBKDF2, 5 попыток, пауза 60 с с удвоением до 15 мин, разблокировка 10 мин в памяти, задать/сменить только с паролем облака. Подарки, серия, PIN — PR командира (K), не дня.
6. **Исключения** — одна структура K: диапазоны `{id, from, to, kind:'sick'|'holiday'}`; L получает их через `exceptionOn(save, day)`.
7. **Даты:** новые темы — до пятницы **12.11.2027** включительно, с **15.11.2027** только практика (`NEW_TOPICS_END = '2027-11-15'`). Мини-пробник: флаг ребёнку пн **7.12.2026**, первый — пт **11.12.2026**. Полные пробники и арена — с **1.09.2027**.
8. **Полночь и незаконченный день.** Минуты начисляются в итоге рейса 2. Рейс 2 пройден, ремонт брошен → начисляется полоса. Рейс 2 не пройден до полуночи → 0, долги переносятся (≤ 8 близнецов). Это решение 4 («60 — трудом»): не доделал — не заработал.
9. **Честный день** (рост питомца, серия) = день, где минуты начислены по `full` или `cap`.
10. **Казахский** — `content/kz_review.json` (C), поле `kzReview` из сохранения убирается.
11. **Флаги и двойник — в неделю 1** (нужны для выкатки 12.10). Привязка сохранения к аккаунту (S2) — до двойника.
12. **Даты миров** — по модели P при темпе 02.10: деңгей 40 — 11.11.2026, 100 — 21.12, 160 — 27.01.2027, 220 — 1.03, 300 — 12.04, 380 — 24.05, 460 — 5.07, 540 — 16.08, 600 — 13.09, 660 — 14.10.2027 (`DESIGN.md` §5 обновить).
13. **Үйренді при нехватке генераторов** — «две наивысшие доступные сложности» (`requiredRungs`) до закрытия долга по генераторам (C).
