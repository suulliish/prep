## Целевая система (как всё должно быть связано)

```
            честная учёба каждый будний день
                          │
        ┌─────────────────┼─────────────────────┐
        ▼                 ▼                     ▼
   МИНУТЫ ИГРЫ       КРИСТАЛЛЫ (тема       МОНЕТЫ
   (реальная         прошла проверку)      (за честную работу)
   награда дня)            │                     │
                           ▼                     ▼
                   ЭНЕРГИЯ = кристаллы     МАСТЕРСКАЯ без конца:
                   открывает МИР           улучшения, питомец растёт,
                           │               отсек корабля за каждый мир
                           ▼
                   БОСС МИРА = смешанный
                   бой по темам мира
                   (проверка, как экзамен)
                           │
                           ▼
                   НАГРАДА МИРА: сундук,
                   костюм / плащ мира,
                   отсек корабля
```

Принципы:
1. **Одна главная шкала — кристаллы** (темы, прошедшие отложенную проверку). Энергия миров, костюмы, «уровень» — производные от неё, а не отдельные числа.
2. **Полученное не отнимается.** Проваленная проверка делает кристалл «тусклым» (его надо починить повтором), но мир, костюм и награды остаются.
3. **Каждая валюта имеет цель до самого экзамена.** Цены и пороги подбираются симулятором (`src/engine/sim.ts`) так, чтобы следующая цель была всегда.
4. **Одно правило — одна функция.** «Честно», «быстро», «наугад», «точность», «освоено», расписание повторения — в `src/engine/rules.ts`, экраны только вызывают.
5. **Одно число — одно место.** Все числа баланса в `content/balance.mjs`; симулятор и код читают оттуда.
6. **На корабле три счётчика:** минуты дня, кристаллы → следующий мир, монеты. Остальное — по событию.

## Этапы

### Этап 0. Видеть систему — этот PR ✅
Карта механик как данные (`content/systems.mjs`), симулятор ученика, 15 инвариантов, `docs/SYSTEMS.md` из карты (`npm run systems`), опись чисел, аудит, журнал решений, тесты на каждом PR, шаблон PR. Поведение игры не меняется.

### Этап 1. Одно правило — одна функция (П1–П3, П6–П9, Ж11) · M
- `src/engine/rules.ts`: `classify(attempt)` → честный / наспех / наугад / свёрнуто; `accuracy(list, kind)`; `isMastered`; все экраны и командир вызывают только её.
- Задача «Еске түсір» не считается отложенной проверкой (П6); медленный неверный ответ идёт в модель знаний (П7); `STUCK_DAYS` от последнего возврата в «изучается» (П8); ошибки урока пишутся в историю с `mode:'lesson'` (П9).
- Закрывает инвариант `one-rule` (частично — понятия «быстро», «честно», «точность», «босс доступен», «половинные монеты», «энергия»).
- Решений семьи не требует.

### Этап 2. Одно число — одно место · M
- `content/balance.mjs`: все числа из `docs/systems/constants.md`; код и симулятор читают отсюда; опись чисел генерируется.
- Новый инвариант: в коде экранов нет «магических» чисел правил (проверка по списку).
- Решений не требует.

### Этап 3. Одна прогрессия (Э2–Э6, Э8, Ж1, Ж12, П4, П5) · L — **нужны решения 1, 3, 4**
- Кристаллы не отнимаются (тусклый кристалл + починка повтором); одно расписание повторения (слить «Еске түсір» и отложенную проверку); одно слово «меңгерілді».
- Энергия = кристаллы; миры привязаны к темам (мир = группа тем), босс мира = смешанный бой по его темам.
- Звёзды копятся в мире и открывают босса и сундук мира; награды за звёзды — на каждый мир.
- Уровень героя = кристаллы (или убрать); ранги свернуть в 3 стата.
- Закрывает: `map-outputs`, `stars-sink`, `outfits-reachable`, `worlds-reachable`, часть `one-rule`.

### Этап 4. Экономика на весь срок (Э1, Э7) · M — **нужны решения 2, 5**
- Мастерская без конца: улучшения предметов, питомец растёт, отсек корабля за каждый мир; цены подбираются симулятором до мая 2028.
- Поломки — только за ошибки последних 7 дней; без половинных монет; «починил — вернул минуты» остаётся.
- Закрывает: `coins-sink`, `ship-recoverable`.

### Этап 5. Данные и облако (Д1–Д5, Т3) · M
- Слияние двух устройств по полям (дни — по дате, поломки и вспоминания — объединением).
- Чистка: план дня удаляется после дня, починенные поломки старше 30 дней, ответ ИИ в журнале обрезается, старое поведение в облаке удаляется.
- Удалить мёртвые поля миграцией (`FIELD_ISSUES`); правила Firestore в репозитории с тестом.
- Закрывает: `cloud-size`, `data-clean`.

### Этап 6. Путь ребёнка (Ж2–Ж10) · M
- Три счётчика на корабле; честные подписи «+N» и порога доп. миссии; копилка выходных видна ребёнку.
- Шаги плана идут подряд без возврата на корабль и портала каждый раз.
- Подтверждение выхода из боя; босс сгорает только после первого ответа; диагностика сохраняет прогресс.
- Командир: PIN нельзя придумать ребёнку (первый вход — только из облака или с паролем облака); подарки с дневным лимитом; исправить «Сменить PIN» и устаревшие подписи.

### Этап 7. Контент и обучение (О1–О9) — **параллельно, самое срочное по срокам**
- До середины ноября: уроки на ноябрь–январь (недостающие темы октября и декабря, десятичные, движение, площади) и генераторы к ним.
- Уравнения и текстовые задачи 5 класса со схемами и шагом «какой это тип задачи»; финал урока + 1–2 задачи экзаменного уровня; рост сложности 1 → 3.
- Режим пробника к декабрю (открывает арену: инвариант `arena-reachable`).
- Визуальная логика, чтение, казахский текст Bolashak; недельный отчёт брату и прогноз готовности.

### Этап 8. Техника (Т1, Т2, Т4) · M
- Версия офлайн-кэша и очистка; разделение кода; 3D не рисует под уроком; озвучка разбора ошибки.

## Как это держится в порядке дальше

- PR не сливается, если красные проверки отличаются от `KNOWN_RED` (новая поломка или забыли вычеркнуть починенное).
- Новая механика или поле сохранения — сначала в `content/systems.mjs`.
- Новое решение семьи — строка в `docs/DECISIONS.md`.
- `npm run systems` обновляет `docs/SYSTEMS.md`: карта, связи, проверки, симуляция на весь срок.
