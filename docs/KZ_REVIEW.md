# Проверка казахского текста носителем (C4)

Решение семьи 02.10: казахский проверяет человек из семьи. Разово 6–8 часов на 36 старых уроков, дальше около 2 часов в неделю на новые; термины как в школьном учебнике Муртазы. Черновики ребёнок видит, пока проверка не закончилась; текст со статусом `fix` ребёнку показывать нельзя (правило в планировщике появится отдельным PR).

## Как это устроено
- **Единица проверки** — кусок текста урока: строка цели, кадр «Көр», вариант ответа, разбор, строка правила. Куски берутся из `content/lessons*.mjs` автоматически (`scripts/review/lib.mjs`), ничего размечать руками не нужно.
- **Статус** лежит в `content/kz_review.json`: `{ id урока или шаблона: { st: 'draft' | 'ok' | 'fix', h, d? } }`. `h` — хэш текста. Текст изменился после `ok` — статус снова `draft`. Тест `tests/kz_review.test.ts` падает, если файл устарел: после правки текста урока или генератора запустите `node scripts/review/status.mjs --init`.
- **Пакет** — один HTML-файл без сети. Внутри: все тексты уроков по шагам, под каждым при необходимости «как прочтёт Бит» (числа и знаки словами, как их услышит ребёнок), термины из `content/glossary.json` с полем «как в учебнике», по 3 образца каждого генератора задач. Отметки хранятся в браузере проверяющего, закрывать страницу можно.

## Что делает Султан
1. Собрать пакет (на этой машине git сломан, но скрипту он не нужен):
   ```bash
   node scripts/review/pack.mjs --id kz-pack-02 --next 12 --out на-вычитку/kz-pack-02.html
   ```
   Варианты отбора: `--queue 6-17` (позиции в очереди тем), `--skills a,b` (явно), `--next N` (первые N тем очереди без статуса `ok`), `--changed` (всё, что не `ok`; для повторной проверки).
2. Отправить файл проверяющему. Он открывает его двойным щелчком в любом браузере, отмечает «✓ Дұрыс» или «✎ Түзету» (правит текст прямо в поле), в конце жмёт «Нәтижені көшіру» и присылает текст.
3. Сохранить присланный текст в файл `результат.json` и применить:
   ```bash
   node scripts/review/apply.mjs результат.json            # статусы и отчёт, тексты уроков не трогает
   node scripts/review/apply.mjs результат.json --patch    # поправки ещё и вносятся в content/lessons*.mjs
   ```
   `--patch` вносит только однозначные места (строка найдена целиком ровно один раз). Остальное попадёт в отчёт `результат-отчёт.md`, там же «было / стало» и термины, которые в учебнике звучат иначе.
4. После `--patch`: озвучить изменённые строки заново (`node scripts/voice/lesson-lines.mjs <тема> > lines.json && python3 scripts/voice/make_voice.py lines.json public/voice/lessons`), затем `npm test`.

## Правила применения ответа
- Урок получает `ok`, только если проверены ВСЕ его куски (`ok` или правка) и все правки подтверждены текстом урока. Есть неотмеченные куски — статус не меняется (`draft`), даже если часть правок уже внесена `--patch`. Не внесённые правки остаются в `d` статуса `fix`.
- Хэш в ответе сверяется с текущим. Отметки в самой странице тоже привязаны к хэшу текста урока, поэтому после правки текста старые отметки по этому уроку не действуют (можно собирать пакет с тем же `--id`).
- Если текст урока изменился после сборки пакета (хэш не совпал), ответ по этому уроку пропускается и попадает в отчёт: собрать пакет заново.
- Генератор: `ok` или `fix` с заметкой (какой образец и как правильно). Образцы детерминированы, при изменении кода генератора хэш меняется и статус возвращается в `draft`.

## Что входит в пакет и что нет
Входит: все строки шагов урока (цель, «Көр», правило, «Өзің», «Неге?», ошибка Глитча, финал, подписи виджетов в `props`, параметры сцен с казахскими словами в `s`), названия блица и 8 образцов его вопросов (блиц генерирует вопросы кодом, образцы берутся с постоянным зерном), название темы и название приёма (доска, реплика Бита, карточка), образцы генераторов задач, термины. Правки вопросов блица и названий не вносятся `--patch` автоматически (блиц рождается функцией `make` в `content/lessons*.mjs`), они попадут в отчёт для ручной правки.

**Не входит:** казахские надписи интерфейса, зашитые в компонентах (реплики Бита вроде «Дәл таптың!», тосты, подписи сцен и виджетов в `src/lesson`, `src/widgets`, `src/screens`, ≈ 160 строк). Их проверка отдельным пакетом после уроков; пока считать непроверенными.

## Если что-то пошло не так
- Ответ не читается: скрипт печатает «Ошибка: …» и ничего не пишет. Нужен текст целиком из кнопки «Нәтижені көшіру».
- После `--patch` статус каждого изменённого урока считается заново отдельным шагом (`finalize.mjs`), он же сверяет, что новый текст действительно попал в урок. Если файл урока после правки не проходит проверку синтаксиса, не записывается ни один файл.
